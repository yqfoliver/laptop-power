# 笔记本电源自适应（LaptopPowerAuto）

一个 **零依赖、完全静默** 的 Windows 笔记本电源管理常驻程序。开机自启后缩在托盘里，根据 **插电/离电、前台程序、负载、温度** 自动切换电源策略，不弹窗、不打扰。

- 单文件 `笔记本电源自适应.exe`（约 9 MB），**不需要管理员权限、不需要装驱动**
- 面板形态：WebView2 网页面板（默认）/ 原生 GDI 窗口
- 17 套回归测试（490+ 项断言），全部离线或走假通道，不碰真硬件
- **不绑定任何机型**：硬件相关判据全部在本机现测（见下方「硬件适配」）

---

## 下载与运行

1. 到 [Releases](../../releases) 下载 `笔记本电源自适应.exe`（或下载源码自行打包）。
2. 双击运行，托盘出现图标；右键可切档、开面板、退出。
3. 面板地址：<http://127.0.0.1:8753/>

> ⚠️ **首次运行若程序"没起来"**：未签名的 PyInstaller 单文件 exe 常被 Microsoft Defender 当成威胁直接删除（症状：开机无自启、日志一行都没有、exe 文件消失）。请把程序所在目录加入 Defender 排除项，再从原位置重新运行。

## 它能做什么

### 五档策略 + 自动判定

| 档位 | 场景 | 主要动作 |
|---|---|---|
| 游戏 | 前台是游戏 | 独显性能模式、功耗分配器把 CPU 瓦数让给 GPU |
| 办公 | Word / 浏览器 | 亮度 75%、待机与睡眠超时收紧 |
| 续航 | 离电日常 | 独显断电、降刷 60Hz、限 CPU 上限、亮度分级 |
| 极限省电 | 低电量 | 在续航基础上进一步压低上限 |
| 平衡 | 交还系统 | **切回系统自带「平衡」计划，不写一个字节** |

### 离电续航

手段分五层，按常见收益从大到小：

1. **降刷 60Hz + 独显 ACPI 级断电**（GPU Eco）
2. **自建电源计划**里的处理器上限、待机/睡眠超时
3. 散热档位跟随
4. **PD 预算控制器**（见下）
5. 亮度分级（离电上限 45%）

### Type-C 弱电源保护（PD 预算控制器）

用 65~100 W 的 Type-C 线打游戏时，整机功耗可能超过线的供电能力，此时电池会被动放电"倒贴"。

控制器从电池充放电速率**实时学习这根线的可持续上限**（不预置任何数值 —— 换线、换充电头都会重新学），并在逼近上限时逐级压制：先限 CPU 上限 → 再降亮度 → 最后降刷新率，**绝不让电池倒贴**。条件好转时按双门槛（绝对余量 25 W 与 62% 比例取严）逐级还原，避免在两档刷新率之间反复抖动。

上限绑定到**供电会话**（AC 接入到断开）：换充电器必然要拔一次电，旧值即作废重新现测。
额定功率在普通权限下读不出来（UCSI 没有用户态通道，`GET_PDOS` 要管理员改注册表重启驱动），只能测量。

#### 供电档位：65 W 与 100 W 是两种机器

只把上限数字改小是不够的 —— 65 W 的余量里独显根本跑不动，压到刚好不放电的结果是又慢又烫。
所以按实测能力自动分档，档位不同，**渲染路径**也不同：

| 实测可持续供电 | 典型充电器 | 档位 | 独显策略 |
|---|---|---|---|
| < 65 W | 65 W PD（实到 ~58 W）、45 W | weak | **强制核显**（ACPI 断电 + 图形偏好覆盖），省下的预算还能给电池充电 |
| 65~85 W | 90 W 砖 | mid | 独显可用但受限，让渡停止点按供电预算收紧 |
| 85~120 W | 100 W PD（实到 ~89 W） | high | 独显可用，逼近上限时提前限帧 |
| > 120 W | 原装适配器 | wall | 不干预 |

「实到」比标称小是因为：PD 砖端效率约 94%，再扣线缆压降与机内 DC-DC；
非 e-mark 的 3 A 线更是直接锁在 60 W。65 W 到系统约 58 W，扣掉平台开销后只剩 46 W 给
CPU+GPU —— 而独显最低也要 35 W 起，加上 CPU 必然超支，所以只能换渲染路径。

档位切换带**不对称滞回**：脱离 weak（要开独显）需超出阈值 8 W 才生效，掉回 weak 立刻生效。
两个方向的代价完全不同 —— 抬错了是电池开始放电，掉慢了是电池正在放电还多放一会儿。

另外，**充电状态下推出来的只是下界**（「电源至少供得出这么多」），不是上限：电池充电功率受
自身充电曲线限制，轻载时永远在充电。只有放电事件标定的值才用于提前限帧，否则 65 W 充电器上
34 W 的日常办公会被误判成「逼近上限」而限帧降刷。

### 功耗分配器

插电游戏时，把 CPU 的瓦数让给独显：按实测功耗动态调 CPU 上限，知道什么时候该让、也知道什么时候该停（GPU 到达能效甜点后收手）。

### 面板

顶部判定当前前台程序，中间五个档位卡，下面是电池续航、散热风扇、功耗分配卡片与 Type-C 供电余量。

## 四条硬性底线

这不是设计偏好，是每次技术选型的裁决依据：

1. **完全静默** —— 不弹窗、不黑窗、不气泡。所有失败只写日志（`boot.log` / `exit.log`）。
2. **零依赖、普通权限** —— 不要管理员、不装驱动。这条直接否决了 SMU 直写 TDP（需要内核驱动）。
3. **不改系统自带计划** —— 系统「平衡」计划一个字节都不动，只用自建计划 `笔记本自适应电源`。
4. **实证优先** —— 文档口径、软件界面、他人数据都只是线索，一切以**运行它的那台机器**的实测为准（这也是不把标定值写进源码的原因）。

## 硬件适配（换一台机器也能用）

**原则：源码里不带任何一台机器的标定数字。** 硬件相关的判据全部在本机现测，
结果写进 `hwprofile.json`（运行时数据，不入库）。第一次启动探测约 1 秒，
之后每 7 天复测一次；全部只读，任何一项失败都静默降级到通用兜底。

| 自动项 | 怎么测 | 测不到时 |
|---|---|---|
| 有没有独显 | NVML / WMI 显示适配器名称 | 视为纯核显机，自动关掉分配器、GPU Eco、核显优先 |
| 独显功耗上限（让渡停止点） | 游戏档实测功耗峰值**学习** | 通用兜底 60 W（宁小勿大） |
| 独显温度线 | NVML slowdown 阈值 −4 ℃ | 87 ℃ |
| 离电降刷目标 | 枚举面板真实存在的刷新率，挑低一档 | 不降（60 Hz 屏不会硬写不支持的频率） |
| 核显能力档位 | 核显型号匹配 | 入门档（只把最轻的游戏交给核显） |
| 厂商通道（ATKACPI） | 驱动能否打开 | 关掉 GPU Eco，不再每轮白试 |
| Type-C 可持续供电 | 充放电速率学习 | 尚未学到则不启用预测 |

`python main.py --hw` 可以打印你这台机器上的适配结果与每个值的来源。

**厂商接口**：程序在**华硕（ATKACPI）机型**上开发，`GPU Eco 独显断电`这一项
目前只有华硕通道可靠。其它品牌（联想、惠普、戴尔、机械革命等）**大概率
不能直接复用厂商接口**，但这些功能不受影响：自建电源计划、处理器上限、
刷新率、亮度、待机超时、PD 预算控制器、核显优先调度（走的是 Windows 系统
自带的「图形首选项」，与品牌无关）。参见：

- [`用WorkBuddy复刻到其它品牌.md`](用WorkBuddy复刻到其它品牌.md) —— 各品牌接口矩阵
- [`项目经验总结.md`](项目经验总结.md) —— 踩坑记录（文中所有实测数字均为开发机示例，仅供量级参考）

想手动接管某个自动项，在 `config.json` 里填一个数字即可 —— **手设值永远优先于自动值**。

## 开机自启

程序默认写注册表 Run 键（直启 exe，不经任何脚本）。若被安全软件拦截，可改用计划任务：

```cmd
schtasks /create /tn "LaptopPowerAuto" /xml "LaptopPowerAuto-task.xml" /f
```

（需在**非沙箱的系统终端**执行；登录触发 + 延迟 15 秒。）

`LaptopPowerAuto-task.xml` 由程序在首次运行时自动生成（含你的真实 exe 路径，不入库）；
也可以用 `python tools/make_task_xml.py` 生成一份模板，手动改好路径再用。

## 已知边界

- **ATKACPI 写入基本被固件拒绝**（性能模式 / 风扇曲线 / 充电阈值 / PPT 写后回读会还原），只有 GPU Eco 可靠。这不是本程序的限制，是厂商固件行为。
- **SMU 直写 TDP 未采用** —— 需要内核驱动 + 管理员，违背零依赖底线。替代方案是实测功耗 → 动态调处理器上限的用户态闭环。
- 显卡功耗计偶发坏值（如 500 W+），PDH 与 NVML 读数都做了清洗与交叉校验。

